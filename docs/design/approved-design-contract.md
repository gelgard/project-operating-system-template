# Approved Design Contract

## Status
Project-populated mandatory contract for every UI/device/experience task.
Projects with no user-facing surface record `not applicable` and evidence;
they do not invent a UI to satisfy the template.

At project bootstrap, replace placeholders with the approved design source, visual rules, responsive states, user guidance requirements, and validation viewports.

Universal rules:
- UI must match the approved design from the first delivered increment.
- Placeholder, generic, or intermediate product UI is forbidden.
- User-facing labels must be understandable for the target user; necessary technical terms require concise contextual help.
- Stable dimensions and responsive constraints must prevent overlap and layout shift.
- Every UI Outcome requires automated browser/device validation. OWNER manual
  walkthrough is required for ready capability milestones, UX decisions,
  Stage merge and release unless the project explicitly requires more.
- Required OWNER validation happens directly in the running application/device;
  screenshots/video/traces are supporting evidence only.
- Walkthrough instructions include exact candidate, prerequisites, launch,
  actions, expected results, failure criteria, cleanup and verdict.
- OWNER is not asked to run developer commands or inspect logs/JSON/DB/hashes;
  agents complete automatable technical validation.
- Visual checks must cover relevant desktop/mobile viewports, loading/empty/error states, and interaction without unintended reloads.
