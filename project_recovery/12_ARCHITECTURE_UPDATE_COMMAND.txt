ARCHITECTURE UPDATE COMMAND

Command:
"обнови архитектурные файлы"

Behavior:
- triggers safe architecture / plan / recovery synchronization
- uses priority:
  1. project_recovery
  2. docs/architecture
  3. docs/plans
  4. ai_tasks
  5. code

Archive-first workflow:
1. detect that architecture sync is needed
2. request the current project archive
3. perform full synchronization against the uploaded archive
4. only after that execute the architecture update command

Rules:
- no full rewrites unless explicitly requested
- only pointwise updates
- preserve all valid data
- sync stage, tasks, next steps
- sync real-time / API layers
- update recovery files
- do not regenerate contextJSON outputs

contextJSON rule:
- existing contextJSON files are frozen historical external exports only
- do not create a new contextJSON/json_<timestamp>.json
- do not update contextJSON/json_spec.md unless a future architecture decision explicitly reintroduces JSON export generation
- no contextJSON artifact is required for architecture sync completion

Context Restore Policy integration:
- this command is a Full restore trigger
- command mapping:
  - `обнови контекст` => Fast restore (default)
  - `обнови полный контекст` => Full restore (forced)
  - `обнови полный контест` => Full restore (forced, typo alias)
- Full restore is also mandatory after:
  - merge/stage transition
  - suspected desync
  - long pause
