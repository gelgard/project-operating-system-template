ARCHITECTURE UPDATE COMMAND

Command:
"обнови архитектурные файлы"

Behavior:
- triggers safe architecture / plan / recovery synchronization
- uses priority:
  1. project_recovery
  2. AGENTS.md
  3. docs/architecture
  4. docs/plans
  5. docs/design
  6. approved user-behavior documentation
  7. ai_tasks
  8. contextJSON archive
  9. code

Workspace-first workflow:
1. run manifest-first Full Restore in the current project workspace
2. reconcile actual version control and preserve dirty/user artifacts
3. request an archive only when the workspace is inaccessible or OWNER makes
   the archive authoritative input
4. identify and apply pointwise architecture/plan/recovery drift
5. validate before commit

Rules:
- no full rewrites unless explicitly requested
- only pointwise updates
- preserve all valid data
- sync stage, tasks, next steps
- sync real-time / API layers
- sync approved design gates when UI obligations change
- audit recent/accepted Change Requests against specification addenda,
  architecture, plans, traceability, recovery, testing, design,
  credential/security, task files/templates, and user-behavior documentation
- apply only missing propagation deltas and explicitly record unaffected layers
- update recovery files
- do not regenerate contextJSON outputs
- verify every executable rule and accepted CR has a trigger binding
- make current-state projections share one state_id
- run python3 scripts/validate_governance_contract.py

contextJSON rule:
- existing contextJSON files are frozen historical external exports only
- do not create a new contextJSON/json_<timestamp>.json
- do not update contextJSON/json_spec.md unless a future architecture decision explicitly reintroduces JSON export generation
- no contextJSON artifact is required for architecture sync completion

Context Restore Policy integration:
- this command is a Full restore trigger
- command mapping:
  - `обнови контекст` => Fast restore (default)
  - `обнови полный контекст` => Full restore (forced)
  - `обнови полный контест` => Full restore (forced, typo alias)
  - `таск выполнен`, `задача выполнена`, `задача готова`, `готово`
    => run current AI task closure validation
- Full restore is also mandatory after:
  - accepted CR propagation
  - merge/stage transition
  - suspected desync
  - agent handoff, context compaction, new day or long pause
