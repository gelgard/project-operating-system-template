TESTING RULES — UNIVERSAL MODE 3.0

1. Map work to Requirement/TEST IDs and separate delivery from acceptance.
2. Standard: focused behavior, static/type/format, relevant build, real
   scenario, diff and secret/path scan.
3. Sensitive: Standard plus adversarial boundary, affected regression,
   ownership/security/persistence, cleanup/rollback and relevant native/live.
4. Integration/Release: fresh deploy/package, full applicable regression,
   cumulative journeys, security/accessibility, rollback and merge canaries.
5. Lower-gate failure blocks higher gates; skipped is NOT RUN.
6. Existing coverage thresholds do not regress. Critical decisions need
   positive/negative evidence; universal 100% is not required.
7. Implementer PASS is untrusted until manager verification.
8. UI gets automated proof. OWNER validates only ready milestone UI directly
   in the running app/device; media is support-only.
9. External/live checks are bounded, explicitly authorized, reversible,
   sanitized and tied to exact candidate identity.
10. Architecture/CR propagation, post-Full-Restore issue and Stage merge run
    scripts/validate_governance_contract.py.
11. Temporary artifacts are removed or intentionally retained as evidence.
12. Diff/whitespace/secret checks pass before commit.
